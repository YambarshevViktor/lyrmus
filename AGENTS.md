# AGENTS.md — Тексты песен (index.html + styles.css + functions/)

## Что это
«Тексты песен»: одна строка поиска → синхронный текст песни с подсветкой в такт музыке.
Без API-ключей на странице, без скачивания музыки. Бэкенда на своём железе нет.

## Файлы
- `index.html` — разметка + JS (стили подключены из `styles.css`).
- `styles.css` — все стили отдельно.
- `functions/api/ytsearch.js` — Pages Function: прокси поиска YouTube (`/api/ytsearch?q=` на том же домене). Отдельный Worker и `server.py` не нужны.
- `functions/api/translate.js` — Pages Function: машинный перевод строк (POST `{sl,tl,q[]}` → `{tr[], failed}`, MyMemory, без ключа; Google gtx не подошёл — 429 автоматическим запросам, проверено 30.10.2026). Анонимно 5000 символов/день; email в env `MYMEMORY_EMAIL` (параметр `de`) поднимает до 50000.

## Запуск и выкладка
- Локально: любой статический сервер, например `python3 -m http.server` в папке, открыть `http://127.0.0.1:8000`. Через `file://` не работает (YouTube IFrame API требует http).
- Продакшн: всё на Cloudflare Pages из одного репозитория — фронт (статика) + поиск музыки (Pages Function `functions/api/ytsearch.js`, тот же домен, ничего вписывать в код не надо). Деплой — push в GitHub (Pages соберёт сам).
- Риск: YouTube может отдавать дата-центру Cloudflare пустую выдачу (бот-защита). Запасной план — ключ YouTube Data API v3 в env функции (никогда на странице), парсинг заменить на `youtube.googleapis.com`.

## Откуда что берётся (показывается в подзаголовке сверху, футера нет)
- Тексты с таймингами — LRCLIB (`https://lrclib.net/api/search`), бесплатно, без ключа. Только записи с `syncedLyrics`; если их нет — страница так и пишет.
- Музыка — YouTube через официальный embed-плеер. Ничего не скачиваем и не храним. Плеер в шапке — он же «обложка».
- LRCLIB не публикует счётчик треков — числа «доступно песен» на странице нет осознанно, формулировка: «вся база LRCLIB с синхронным текстом».

## Как работает поиск
1. Текст: страница идёт напрямую в `https://lrclib.net/api/search` (у LRCLIB открыт CORS), до 3 попыток с паузой 1с — LRCLIB иногда отдаёт спорадический 503. Дальше фильтр `synced` → лучший по совпадению слов (`scoreLyric`), до 8 вариантов в списке.
2. Видео: сначала same-origin `/api/ytsearch?q=` (Pages Function в том же проекте, парсинг `videoRenderer` из HTML выдачи YouTube: videoId, title, channel, duration, до 12 шт). Фолбэк — публичные Piped/Invidious (ненадёжны, мёртвые не чинить — они умирают сами).
3. Ранжирование `rankVideos`: Topic-каналы +10, official audio +6/+4, lyric +2; клипы −6, live −3, acoustic/remix −4; длительность ±8с от трека +5, расхождение >20с −8; мусор по `JUNK_RE` −10.
4. Фильтр `suitableVideos` (показываем только годное): не мусор, длительность в пределах ±30с от трека, ≥1 общее слово (длиной >2) с «артист + название». Мусор скрыт всегда, без галочки. Если годного нет — честное предупреждение + топ-3 как fallback.
5. Подключение `connectVideo`: перебор до 8 кандидатов (embed-запреты 101/150 обходятся выбором другой версии). `createPlayer` пересоздаёт `#player` через `playerBox.innerHTML` (иначе повторные запуски ломаются — YT заменяет div на iframe). Таймауты: 2.5с окно ошибки после ready, 20с failsafe, `ensureApi` 15с (детект блокировщиков).

## Синхронизация текста
- `parseLRC`: строки `[mm:ss.xx]` + честная пословная разметка enhanced (`<mm:ss.xx>`), иначе авто-интерполяция слов по длине строки.
- rAF-цикл читает `player.getCurrentTime()+offset` → `updateActive`. Клик по строке = `seekTo`. Сдвиг ±0.5с кнопками.
- Дефолт — построчный режим (`body data-mode="lines"`), тогл «Строки / Слова».
- При PLAYING оба списка выбора скрыты, при PAUSED/ENDED показываются обратно.
- Перевод: если в тексте >70% латиницы — страница шлёт строки в `/api/translate` (MyMemory, без ключа; язык источника угадывает `guessLang`: кана→ja, хангыль→ko, иероглифы→zh-CN, иначе en), перевод появляется под строкой мелким серым (`.line .tr`, 15px). Кэш переводов — `trCache` по id версии текста. Русское не переводим. Статус виден в `syncLabel` (`syncBase` + ` • перевожу… / перевод готов / без перевода (причина)`).

## Стиль (решения пользователя, не менять молча)
- Шрифт везде Inter (Google Fonts `<link>` + системный фолбэк; `input,button{font-family:inherit}`).
- Ссылки в подзаголовке — цветом обычного текста (`inherit`), белые только при наведении (`.sub a:hover`).
- Карточка прозрачная без паддингов (`background:none;border:0;padding:0`). Футера нет — атрибуция в подзаголовке сверху («Тексты — LRCLIB, музыка — YouTube…»).
- Страница в размер экрана: `.wrap` — `100dvh` flex-колонка, `.card` — `flex:1`, текст занимает остаток (`.lyrics flex:1`), списки выбора со своим скроллом (`max-height:24vh`).
- Текст песни: 32px, weight 700, line-height 1.0, gap 0.6em, `.line` padding 12px. Отдельной статус-строки нет — весь статус (`setStatus`) пишется в подсказку `.hintbar` над текстом (по центру, 16px, отступ сверху 22px от шапки; стартовый текст «Здесь появится текст…» там же). Края блока текста уходят в прозрачность (mask-gradient: сверху 10%, снизу 38%), плюс `padding-bottom:30vh`, чтобы последние строки доезжали до третьей позиции. Будущие строки — серые `#8e96a3`, спетые — те же, но прозрачнее (`rgba(142,150,163,.38)`). Активная — белая, без фона и обводки, держится третьей сверху (`scrollIntoView block:'start'` + `scroll-padding-top:140px`).

## Правила для агентов
- Никаких API-ключей на странице. Музыку не скачивать — только официальный embed.
- После правок: извлечь инлайн-`<script>` и прогнать `node --check` (и `functions/api/ytsearch.js` как `.mjs`); проверить функцию прямым запросом `…/api/ytsearch?q=` на проде; обновить этот файл, если изменилось поведение.
